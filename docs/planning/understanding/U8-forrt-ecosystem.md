### 2.1 flora-replication-atlas — CLOSEST TO OUR WIKI
- **Purpose:** "Search by DOI, title, or author to instantly check whether a study has been replicated"; generates one static landing page per original DOI.
- **Status:** mature, deployed, pushed daily (last commit "chore: update sitemap" 2026-09-07 06:00 UTC via `.github/workflows/update-sitemap.yml`; `deploy.yml` on push; `refresh-data.yml` runs `scripts/refresh_data.py`). Live: 4,717 originals, browse pages by outcome (979 successful / 772 failed / 585 mixed / 248 no-outcome / 2,133 originals with no replication on record — i.e. the atlas also lists *replication papers* as pages), by decade, by journal (Psych Sci 214, JPSP 138, OSF 120, J Applied Econometrics 110, AER 101 …).
- **Stack:** SolidJS 1.9 + @solidjs/router, Vite 7, Tailwind 4 + daisyUI 5, TypeScript; prerender script `scripts/prerender-doi-pages.js` (Node, `@resvg/resvg-js` for OG PNGs) writes `dist/doi/<doi>/index.html` + `og.png`; `scripts/browse-pages.js`; `scripts/generate-sitemap.js`; `scripts/copy-index2.js`. Data at build time from `https://rep-api.forrt.org/v1/dois` + POST `/original-lookup` in batches of 100, 5 concurrent.
- **Licence:** CC0-1.0 (LICENSE file) → **reuse verbatim allowed**.
- **Data model** (`src/@types/index.d.ts`, `src/schema/results.json`): `OriginalPaper{doi, doi_hash, title, authors[{given,family,sequence,ORCID?}], journal, year, volume, issue, pages, apa_ref, bibtex_ref, url, types[], record{stats{n_replications_total,…}, replications[], originals[], reproductions[]}, citation_timeline{entries[{year,only,with_successful,with_failed,with_mixed}]}, n_citations, outcome_mix, replication_year_counts, first_replication_year, first_replication_outcome}`; `ReplicationItem{doi, doi_hash, type, title, authors, journal, year, …, outcome (successful|failed|mixed|partial|9 reproduction two-axis labels), outcome_quote, outcome_quote_source}`.
- **Page content (viewed live for 10.1126/science.1239918):** title/authors/venue/DOI, "Has this study been replicated? The atlas records 6 replications … 3 failed, 2 mixed, 1 successful", then each replication: title (linked if it has its own atlas page), first author et al. (year), "Outcome recorded: X", outcome_quote (≤300 chars), "View paper"; a "ring" of 6 related links for crawlability; JSON-LD `ScholarlyArticle` with `subjectOf` attempts. UI (SPA) adds: search by DOI/title/author/year, multi-DOI batch, `?set=` shareable DOI lists, Unpaywall PDF links, APA/BibTeX copy, PDF export, "Citation Impact" modal (`CitationImpactModal.tsx`, from the OpenCitations timeline), bug-report modal, "Reference import" modal (paste a reference list → check all).
- **What it does NOT have:** effect/finding identity (pages are per paper; a finding replicated across 3 originals = 3 pages), effect sizes / Ns / any FReD statistics, closeness/design coding, timelines with narrative, forecasts, game, topic/discipline pages, author pages, "what does the literature say" citation contexts, retraction flags (extension has them, atlas does not), curation state.
- **`scripts/refresh_data.py`** (Python, boto3/pandas/statsmodels/requests): FLoRA × OpenCitations v2 (`/index/api/v2/citations/doi:<doi>`), 0.7 s delay, 30-day disk cache, time-budgeted; builds per-original citation timeline split by whether the citing work also cites a successful/failed/mixed replication; writes into DynamoDB `DATA_TABLE`. **Reusable verbatim (CC0)** for our "citations kept rising after the failed replication" sparkline.
- **Compare to ours:** it is the paper-centric "has it been replicated?" lookup done well and SEO-optimised (5,131-URL sitemap, JSON-LD, OG images). We must not rebuild this. Our pages should be *effect-centric* and link out to the atlas page per DOI (and the atlas could link back).

### 2.2 flora-backend — the API
- **Purpose:** serverless read-only API behind Zotero plugin, atlas, extension, preprint-notifier.
- **Status:** deployed (`rep-api.forrt.org`, API Gateway HTTP v2, Lambda Node 24, eu-central-1), pushed 2026-08-27. No tests.
- **Stack:** Serverless Framework v3 + esbuild; three on-demand DynamoDB tables `zotero-replication-backend-<stage>-{prefix,doi,search}`; IAM read-only. ETL `etl/seed_prefixes.py` (boto3/pandas/ftfy) reads FLoRA CSV (needs `doi_o, doi_o_hash, type` [+ `doi_r, doi_r_hash`]), `PREFIX_LEN=3`, `SEARCH_CHUNK_SIZE=500`, `CLEAR_TABLES=1` (full rebuild). Input is `output/flora_filtered.csv` (per fred-data `R/filter_flora.R`: drops invalid identifiers 205, Boyce mega-paper 140, OSF registrations 12, retracted 1 → 2,457 rows).
- **Endpoints:** `/v1/prefix-lookup`, `/v1/original-lookup`, `/v1/dois`, `/v1/search` (Fuse weights title .6 / authors .25 / year .1 / rep_authors .05; wildcards; `paperTypes` expands linked papers both directions; limit ≤1000; 6 MB Lambda cap). Record derived fields (`outcome_mix`, `replication_year_counts`, `first_replication_year/outcome`, `citation_timeline`, `n_citations`) are hoisted to top level by `src/recordFields.ts`.
- **Licence:** ISC per README, no file.
- **Reuse:** consume live (§C). Don't clone the infra; our static build can hit `/v1/dois` + `/original-lookup` exactly as `prerender-doi-pages.js` does (≈48 POSTs for 4,722 DOIs) — or just read flora.csv directly (same content plus outcome quotes; the API adds Crossref-formatted apa/bibtex refs and the citation timeline).

### 2.5 flora-extractor — the discovery/extraction engine (FORRT's "find more replications")
- **Purpose:** discover, screen, extract (target original + outcome) replication/reproduction papers for FLoRA; feeds flora-validation.
- **Status:** active (pushed 2026-09-02); "lockdown campaign" completed 2026-08-16 (handover.html). Maintainer Lukas Wallrich; Claude-Code-driven development (60 KB CLAUDE.md, `.claude/settings.json`, AGENTS.md).
- **Stack:** Python 3 (`.venv`), pyarrow/parquet, DuckDB routing store, **Postgres/Supabase for claims + permanent verdicts** (`db/migrations/0001..0005`), Hugging Face private dataset repos for the survivor pool (~2–7 GB parquet) and shared API/LLM caches, SQLite abstract store, GROBID (optional), Flask read-only dashboard (`validate/app.py`, localhost:5001). Env: `RESEARCHER_EMAIL, GEMINI_API_KEY, OPENAI_API_KEY, OPENROUTER_API_KEY, SUPABASE_SERVICE_KEY (required by every claimed --run), HF_TOKEN, ELSEVIER_API_KEY`.
- **Licence:** README says MIT; **no LICENSE file** → ask.
- **Pipeline (search → screen → extract → validate):**
  - *Stage 1 search* (`search/run_search.py --scan`, `search/snapshot_scan.py`): one scan of the full OpenAlex bulk snapshot (2,446 parquet partitions, 725 GB, ~510M works; run on EC2 in-region, docs/aws-snapshot-scan.md). Gate = `filter/phrase_detection.py`: `REPLICATION_STEM_PATTERN = (?i)replicat|replicab|reproduc|reanalys|re-analys|reanalyz|re-analyz|replikat|réplicat|replicaci|replicaç|replicazion|reproduç|reproduzi|追試|반복검증|재검증` over title + raw abstract inverted index, OR OpenAlex concept `C12590798` (Replication (statistics), 263k works) / `C9893847` (Reproducibility, 121k). Keeps <1% → **survivor pool 5,128,211 works** (5,146,160 rows; 14,744 OSF-guid aliases). API-harvest legs (S2 search, Replication Network, I4R) retired to `wip/api-harvest-sources`.
  - *Stage 2 filter* (`filter/engine`, declarative JSON specs in `filter/spec/`: replication-claim-title-strong/-broad/-text/-cited-title/-residual, replication-signal, reproduction-signal, replication-probe, osf-registration-completed/-protocol, deposit-registrant, figshare-attachment, not-a-paper-{doi,title,abstract}, not-a-report-type, not-a-study-type; `CONVENTIONS.md` precedence/pile policy; `aliases.json`). Whitelist: rules route into piles `discard / screen_expensive / screen_cheap / needs_human / pending`; **only LLMs admit**. Current release `16d370746b45`: 558,749 discard, **4,561,702 pending (untouched by design)**, 7,760 screen_expensive. LLM screen = 2 voters, `SCREENING_MODEL_1 = deepseek/deepseek-v4-flash` (effort low, via OpenRouter) + `SCREENING_MODEL_2 = gpt-5.4-mini` (low); gate G-unanimous (discard only if all votes `none`). Prompt `_CLASSIFY_PROMPT` v3.3 (copy in `analysis/screening_eval/prompt_v33.txt`): output `{classification ∈ replication|reproduction|both|none|unclear, confident, categories[11-value enum: clearly_declared, self_retest, measurement_validation, context_transfer, incidental_finding, initial_validation, tool_benchmark, builds_on_literature, terminology_only, about_replication, other], evidence_quote, reasoning}` with explicit qualifies/does-not-qualify rules (internal replication, tool benchmark, first validation, comment without analysis, DNA/viral senses…). Cheap pre-screen tier (qwen3-30b + mistral-small-24b) exists but is dormant (`analysis/prescreen_eval/REPORT.md`: 87% negatives discarded, 0/567 gold positives lost, but CI up to 0.67%).
  - *Stage 3 extract* (`extract/tier.py --run`, `extract/export.py --release <id>`): resolution ladder (`extract/link_original.py`, ladder v26): title-pattern match → rule-based citation/candidate match (OpenAlex `referenced_works`/cited candidates) → abstract LLM over candidates → reference-list LLM pick (`llm_references`) → pooled title search (CrossRef + OpenAlex + author-year shortlist; `llm_title_search`, `llm_author_year_search`) → PDF acquisition waterfall (Unpaywall/CORE/arXiv/OSF/EPMC JATS/OpenAlex GROBID XML/HTML landing) + full-text LLM. One prompt asks BOTH target and outcome (`build_target_outcome_prompt`; `@smith2009` keyed candidate namespace via `shared/target_keys.py`; accept only `match_certain`). `LINKING_MODEL = OUTCOME_MODEL = gpt-5.6-luna` (effort medium), `PDF_PARSE_MODEL = gemini-3.1-flash-lite`. Cold confirmation calls: `confirm_keyed_original` (keyed links) and `confirm_search_original` grading `clearly_target|likely_target|unlikely_target|clearly_not_target` → sets `link_confidence`. DOI verification `shared/doi_verify.py` (CrossRef→OpenAlex, 3 tiers). Outcome rules prompt (`_OUTCOME_RULES_SRC`): authors' OVERALL verdict decides; else their comparisons to the original (explicit or implicit, with two tests); else `cannot_be_determined`; vocabulary success/failure/mixed/descriptive/flawed/uninformative/cannot_be_determined; reproductions coded on two axes (computation × robustness). `uninformative` = authors' verdict, `cannot_be_determined` = pipeline's.
  - *Stage 4* = read-only Flask dashboard; real validation in flora-validation.
- **Measured quality (FORRT's own, in-sample):** screen (`analysis/screening_eval/report_v33.md`): on 320 positives (300 FLoRA + 10 human + 10 held-out) and 70 hard negatives: **0–1 settled misses, 84–89% hard-negative discard**; per-model sensitivity 98–100%, specificity 88–100%; run-to-run variance ±1 case. ## 6. (D) Risks and positioning

- **Are we about to duplicate the atlas? Yes, if we build paper-centric "has DOI X been replicated" pages.** The atlas already has 4,717 SEO'd pages, JSON-LD, OG images, a daily-refreshed API, a browser extension and a Zotero plugin pointing at it, and CC0 code. Rebuilding that would be worse than theirs and would split search traffic. **Do not build /paper/<doi> as a primary entity.** Our paper pages should be thin redirects/embeds that link to `forrt.org/flora-replication-atlas/doi/<doi>/`.
- **What is genuinely ours:** effect identity + aliases + lineage; three lenses per attempt using FReD stats + legacy closeness + author quotes; multi-criterion verdicts per effect (not per dataset); narrative evidence timeline with curation state; the game (probabilistic, calibrated, stratified, with FORRT's own author-overlap/journal/p-value base rates as reveal cues); forecasts on not-yet-replicated effects settled by FLoRA; textbook/Wikipedia overlay; effect-level leaderboards (most-cited unreplicated, dependency chains); a *public* discovery queue (their 3k machine-extracted candidates + our citation-graph finds), with a measured recall harness FORRT lacks; topic/subfield pages (OpenAlex topics; their `disciplines.json` is journal-level).
- **Positioning:** "an independent effect-level explorer built on FORRT data, contributing back" — concretely: (1) cite `output/citation.txt` on every page, label FLoRA/FReD provenance per row; (2) link every DOI to the atlas and every effect page back to FORRT's submit form; (3) push reviewed candidates to FORRT in their entry-sheet format and offer our citation-graph leg as the harvester their issue #150 wants; (4) propose our effect-level view as a flora-explorer tab (their CONTRIBUTING invites it) and list the game in the games portal; (5) talk to Wallrich/Röseler early (they run hackathons; the extractor and validation repos are unlicensed, so reuse of *code* needs their nod; data is CC-BY).
- **Other risks:** rep-api has no SLA and `/search` CORS is forrt.org-only (call it at build time, never from the browser); FLoRA outcome coding has known inconsistencies (their own `dup_outcome_conflicts.csv`, `cannot_be_determined` vs `uninformative` distinction, 53% success share in machine-extracted rows vs 42% in FLoRA — selection effect from reference-list links); FReD effect_id is a row counter and `entry_id` is buggy (U5); the extractor's outputs are LLM-coded and *unvalidated* — must never be shown as FORRT-validated; several FORRT front-ends were themselves generated with Gemini/Claude (journalranking, replicatethis, tenure-run), i.e. they will keep shipping quick dashboards fast — compete on depth (effects, lenses, game), not on dashboards.
