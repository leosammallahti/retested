## 1. Headline findings (read this first)

1. **The legacy FReD snapshot is richer than the current FReD.** Root `fred_database_english.csv` (4,376 x 100) has the *identical* column set as `data/raw/forrt/osf/version-history/FReD_2.4.1_2025-06-25.xlsx` sheet "Data" (4,661 x 100) — it is that sheet minus ~285 rows. The current `output_FReD.xlsx` (2,164 x 56) has only **786 unique original DOIs vs 1,678 in legacy** (intersection 568 raw / 594 normalised; 1,110 legacy DOIs absent from current), and it **dropped**: `effect` (name; 2,620 filled), all ten `closeness_*` codings (163–180 filled each), `power` (833), `ci.lower/upper_original` (877) and `_replication` (~827), `preregistration` URL (746), `osf_link` (1,716), `same_design` (456), `same_test` (317), `result` (1,396: 718 informative failure / 662 success / 12 inconclusive), `outcome` (694 signal/no-signal consistency codes), `significant_original/replication` (906/859), `validated`(3,573)/`validated_person`, `contributors` (2,800), `notes` (1,735), `differences` (355), `teststatistic_orig/rep` (734/247), `es_*_RRR`, `orig_journal` (2,089), `source` (4,192), `date_entered`, `exclusion` (586), `id_sample`, `published_rep`, `nesting`, `original_authors`. Current adds instead: title/author/journal/year/volume/issue/pages for o & r, bibtex, language, `author_overlap(_pct)`, `claim_text_o` (2,131 filled vs 28 in legacy), `es_repr_o/r`, `nested_o/r`, `prereg_o/r` flags (58/1,175), `reported_success` (successful 985, failed 787, mixed 359, stat-successful-but-flawed 18, descriptive-only 10, uninformative 5) + quote + source, `url_r`. `fred_id` in current == legacy `id` (645 of 1,116 current fred_ids match a legacy id). `entry_id` in current is constant (nunique = 1) — useless. **=> Merge legacy v2.4.1 coding onto current by `fred_id`/`id` and by DOI pair; keep legacy rows whose DOI is in neither current FReD nor FLoRA (1,630 rows; 174 with `result`, 209 with `es_original`; mostly source FORRT 658, Anna Van 't Veer 252, Individual submissions 161, ML1 107, AI search 96, OSC 2015 57).**
2. **`docx_parsed_entries.json` (362 effects) is a parse of FORRT's public "Replications & Reversals" list, not an independent curation.** The 2.4.1 workbook has a sheet "Reversals Effects" (583 rows: discipline, effect original, effect renamed, alternative names, description, status — only discipline/effect/description filled) and the "FORRT R&R (editable)" sheet (1,406 x 73). 218 of 361 docx names match the sheet's "effect original" exactly; the sheet has 365 names the docx lacks (the docx is an older/partial snapshot; `psychology_replications.csv` = 437 entries is a slightly larger parse of the same .docx with two more categories: Neuroscience (humans) 25, Evolutionary Linguistics 1). What the docx adds that FORRT's sheet lacks: a **status** per effect (replicated ~113 / mixed ~117 / not replicated ~101 / reversed 9 / unknown ~21 after normalising messy strings), `original_paper` (quoted title + author + year + per-study n + Google-Scholar citation count for 341 entries), `critiques` (replication authors + year + n + GS cites), `original_es` (300 filled) and `replication_es` (302 filled, free text). **No DOIs at all** (0/362); years present in 351/353 entries; quoted original titles in 329.
3. **docx -> FORRT DOI linkage is feasible via titles, not names.** Fuzzy title match (ratio ≥ 90) of the 322 usable quoted titles: 100 hit FLoRA `title_o`, 73 hit current FReD `title_o`, 211 hit legacy `ref_original` (partial ≥ 92); 219 (68%) hit at least one. Name-based matching is poor: strict `fuzz.ratio ≥ 85` of names vs current FReD `tags` = 0/362; vs current `description` partial ≥ 90 = 30; token-set matches ≥ 90 vs `tags` = 45 but those are junk ("priming" == "Priming"). Surname+year extractable for 317 entries; 124 co-occur in some FLoRA `apa_ref_o`.
4. **Citation network exists but is partial.** `citation_dois.json` = for **1,688 legacy original DOIs** (62 errors) the OpenAlex `ref_dois` (68,076 total; 50,215 unique) and `citing_dois` (353,974 total; 271,217 unique) — but citing lists are **capped at 600 per DOI** (1,220 DOIs truncated) and carry **no year**. `citation_data.json` (29 MB) has full metadata (year, journal, first author, institution, topic) for refs+citers, but only for the **first 200 DOIs** (metadata.processed=200) and capped at 1,000 citers. Internal network: 376 FReD originals are cited by other FReD originals (1,149 internal edges) -> `fred_internal_citations.json`. `citation_by_outcome_analysis.json` already computes "high-profile failures" (e.g. Availability heuristic 1973, 9,660 cites; Dweck implicit theories 2007, 3,581; chameleon effect 1999, 3,523; Bargh automaticity 1996, 2,348) from 185 success / 156 failure DOIs. **"Most-cited unreplicated effects" is buildable today from `openalex_original_enrichment_full.json` (cited_by_count + counts_by_year in `raw`) joined to outcome. "Citations after failed replication" needs per-year citation counts: `raw.counts_by_year` (OpenAlex, last ~10 years) is present for 1,596 DOIs — enough for a "did citations drop after the replication year?" feature without re-fetching; full citer-level timelines would need a re-fetch of citing works with years (citation_dois lacks them).**
5. **OpenAlex enrichment for originals is essentially complete**: `openalex_original_enrichment_full.json` (40 MB) = 1,623 DOIs (1,596 ok, 27 not_found) each with a flattened `data` block (27 fields) **and the raw OpenAlex work record** (authorships, institutions, topics, concepts, keywords, mesh, fwci, citation_normalized_percentile, counts_by_year, referenced_works, related_works, abstract_inverted_index, locations, best_oa_location, funders, SDGs…). Abstracts: `abstract_enrichment.json` 1,632 DOIs, 1,420 with abstract (pubmed 901, openalex 267, crossref 214, tldr 36, S2 2) + 713 Semantic Scholar TL;DRs. Everything is re-fetchable from public APIs, but the cached copies save ~2 hours of polite API time — keep as DER caches.
6. **Third-party raw datasets present**: `osc_2015_rpp_data.csv` (RP:P master table, 168 x 138, latin-1 encoded), `ml4_full_data.csv` (Many Labs 4 participant-level, 2,281 x 87; `ml4_results.csv` 17 site-level rows), `manybabies_mb1_data.csv` (MB1 trial-level, 19,603 x 85, 67 labs, 1,955 infants; latin-1). All are public GitHub/OSF downloads (github.com/raklein/ml4, github.com/manybabies/mb1-analysis-public, osf.io/ezcuj) — re-downloadable, so DER, but valuable for "drill into a multi-site project" pages.
7. **Security**: 47 scripts hard-code an OpenRouter API key (`sk-or-v1-…`, e.g. `enrich_osc2015.py`, `enrich_effect_names.py`, all `test_taxonomy_v*.py`). Rotate the key; never commit those scripts as-is.
8. **Broken/junk**: `dataset_publication.zip` (246 B) and `replication_database.zip` (17 KB) are **not zips** — the first is an OSF 500-error JSON, the second is an R script (`# Download and format rd Submissions (via sosci)` — the FReD/ReD soscisurvey ingest script, mildly interesting as documentation of the FORRT pipeline). `fred_extdata.csv`, `fred_rpackage_data.csv`, `manybabies_mb1_metadata.csv` are 14-byte "404: Not Found" files. `fred_database_english.json` (17 MB) is **invalid JSON** (bare `NaN` literals). `osf_page.html` is an OSF SPA shell.

Surname+year for 317; found in FLoRA apa_ref_o for 124 (39%).
- Recommendation: treat the docx as a *curated overlay* keyed by a slug of the effect name; resolve `original_paper` -> DOI via Crossref `query.bibliographic` on the quoted title + surname + year (expected ≥ 90% resolvable — all 329 titled entries are famous papers), then join to FReD/FLoRA by `doi_o`. The remaining 143 docx-only names vs FORRT's 583-row sheet suggest fetching the live FORRT R&R list (FORRT sheet has 365 effects the docx lacks) rather than relying on the docx.

### 6.2 Citation network — what exists, what it can power
- Node set = 1,688 legacy original DOIs (not the current 786). Edges: `ref_dois` (outgoing, complete) and `citing_dois` (incoming, capped 600, no years). `citation_data.json` adds years/journals/authors for citers of the first 200 DOIs only.
- Ready-to-ship features: (a) **most-cited effects by outcome** (`openalex_original_enrichment_full.json` cited_by_count x legacy result/current reported_success; already prototyped in `citation_by_outcome_analysis.json`); (b) **"this original is cited by N other FReD originals"** (internal network, 376 nodes / 1,149 edges); (c) **"papers that cite many FReD studies"** = meta-science/review papers (e.g. 10.3758/s13428-017-0967-6 cites 66) — good for discovering new replication reports; (d) **citations-per-year vs replication year** from `raw.counts_by_year` (OpenAlex gives ~last 10–12 years) for 1,596 originals — enough for a "did the field notice?" sparkline.
- Not possible without re-fetch: citer-level "citations after failed replication" for all DOIs (need years for citing works; `citing_dois` has none), and anything for the 1,110 legacy-only DOIs if the node set is rebuilt from current FReD only.

### 6.3 fred_per_* aggregation method (inferred from the numbers)
- Built from `fred_database_english.csv` (legacy) joined to OpenAlex broad_category. `per_original_study` = groupby `doi_original` (1,688 groups = 4,295 rows with a DOI); `per_experiment` = groupby (`doi_original`,`study_original`) (1,991 groups, 4,375 rows); `per_effect` = groupby `effect` (440 groups covering only the 2,620 rows with an effect name). Success/failure counted from the legacy `result` column only (1,396 non-null) -> 1,339/1,688 originals get `no_outcome_data`; the new build should compute outcomes with the FReD R package's 7 criteria and current `reported_success`.

### 6.4 OSC 2015 / ML4 / ManyBabies

### 6.5 forrt_replications_reversals vs psychology_replications vs fred_database_english
- `forrt_replications_reversals.csv` = the workbook's "FORRT R&R (editable)" sheet (FORRT's own coding of the Replications & Reversals list into DOI pairs; 1,345 rows, 558 effect names, 1,260 doi_original / 917 doi_replication, almost no effect sizes or results). `psychology_replications.csv` = text parse of the .docx (437 rows, no DOIs). `fred_database_english.csv` = the full legacy Data sheet where 1,225 rows have `source == FORRT` (the R&R rows after validation/ES coding). So: docx (names+status+prose) -> R&R sheet (names -> DOI pairs) -> Data sheet (DOI pairs + ES/n/result). The name column is the join key between the first two (208 exact matches), DOI pairs between the last two.
